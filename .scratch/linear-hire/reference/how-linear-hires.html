How Linear hires

Compressed from Linear first-party posts. Re-read the sources before a loop; this page is for recall.

Scorecard

  • Craft — depth, details that matter, quality vs extra motion.
  • Judgment — tradeoffs with incomplete info; no OKRs, no A/B as the decision machine.
  • Ownership — problem from idea to shipped; shape, decide, talk to users, write progress.
  • Clarity — simple, direct; do not hide weak ideas in complexity.
  • Fit — small teams, high surface area, few meetings; you must seek feedback yourself.

Source: How we hire

Stages

  1. Careers application (Talent reads all). Compensation on first recruiter call.
  2. 3–4 conversations: recruiter/HM, then coding / architecture / design decisions.
  3. Panel: strong-yes heavy before trial. Trial is not a weed-out of random applicants.
  4. Paid work trial, 2–5 days (senior often 5). Kickoff → you lead check-in → presentation.
  5. Independent written feedback, blind vote, anything but strong yes is a no.

Sources: How we hire, Work trials

How the job actually runs

  • Teams of 2–4; project lead often engineer or designer; then disband.
  • Short specs (context + intent). Feature flags, weekly written Slack updates.
  • Zero-bugs with SLAs. Quality Wednesdays. Feature roasts. Goalie for inbound.
  • Remote-first; optional hubs; yearly company offsite. Europe is in-geo for this JD.

Source: Designing remote work
